# Architecture

```
cmd/2fa/                  entry point (cobra + flags)
internal/core/crypto/     Argon2id KDF + AES-256-GCM AEAD + .2fa container
internal/core/totp/       RFC 6238 / RFC 4226 (self-contained, no deps)
internal/core/vault/      SQLite store + Init/Unlock/Lock lifecycle
internal/core/otpauth/    otpauth:// URI parser
internal/core/importexport/  Sniff + Aegis / .2fa / otpauth importers & exporters
internal/tui/             bubbletea TUI (three columns)
internal/app/web/         net/http API + embedded static (HTML/JS)
```

## Data flow

```
            ┌──────────┐
            │ User CLI │─────── cobra commands ─────┐
            └──────────┘                            │
                                                    ▼
                                            ┌──────────────┐
                                            │ vault.Vault  │
                                            │ (in-memory)  │
                                            └──────┬───────┘
                                                   │ SQL
                                                   ▼
                                          ┌────────────────┐
                                          │ ~/.2fa/        │
                                          │  vault.sqlite  │
                                          │  machine.key   │
                                          └────────────────┘

TUI / Web / GUI all open the same `vault.Vault` and call its methods.
They never touch the DB directly.
```

## Security model: row-level vs full DB

Tradeoffs considered:

| Option | Pros | Cons |
|---|---|---|
| Full-DB SQLCipher | Transparent; existing tools work | CGO + system dep; cross-compile pain |
| Per-row AEAD (chosen) | Pure Go, no deps, no DB-size limit | AAD/IV bookkeeping |
| Per-file AEAD wrap | Simplest code | Re-encrypt full DB on every write; slow for big vaults |

For a TOTP vault (< 1000 rows typical), per-row is the right tradeoff.
A row's sensitive columns (`secret`, `notes`, `backup_codes`) are sealed
with the in-memory KEK; the `issuer` and `account` stay in plaintext so
SQL can sort and filter without decryption.

## KEK lifecycle

```
1. Vault.Init(mode, password)
   ├─ ModeNoPassword: KEK = SHA256(machine_id || vault_salt)
   │                  fall-back to persisted random key (containers without /etc/machine-id)
   └─ ModePassword:   KEK = Argon2id(password, vault_salt)
   KEK stays in *Store.kek (32 bytes) for the process lifetime.
   On Lock: zero the buffer.

2. SealVerifier(KEK) → GCM-encrypt "OK" with random nonce, save to kv_meta.
   This is the only way to detect wrong-password at unlock without trying
   to decrypt a real row (which would be ambiguous for empty vaults).

3. On Unlock:
   - ModePassword: derive KEK from password, attempt Open(verifier).
     If "OK", keep KEK; else zero and report "wrong password".
   - ModeNoPassword: derive KEK from machine_id, attempt Open(verifier).
```

## Container format (`.2fa`)

```
[4]  Magic            "2FA\x01"  identifies our format
[1]  Version          1
[1]  KDF ID           1 = Argon2id
[4]  Argon2 time      uint32 BE (iterations)
[4]  Argon2 memory    uint32 BE (KiB)
[1]  Argon2 threads   uint8
[16] KDF salt         (Argon2id salt)
[16] MAC salt         (separate salt for HMAC key derivation)
[12] Nonce            (GCM nonce, generated by Seal)
[4]  Ciphertext len   uint32 BE
[N]  Ciphertext       (GCM ciphertext without nonce; tag is the last 16 B)
[4]  CRC32            uint32 LE  covers magic..ciphertext; detects truncation
[32] SHA-256 keyed MAC of magic..CRC; detects tampering beyond truncation
```

AAD for GCM = first 47 bytes (magic..mac_salt), explicitly excluding
the nonce — keeps AAD independent of randomness.

## Compatibility

| Format | Read | Write |
|---|---|---|

## Performance

| Operation | Time |
|---|---|
| Init (password) | ~150 ms (Argon2id) |
| Init (no-password) | <1 ms |
| Unlock (password) | ~150 ms |
| List 100 secrets | ~5 ms |
| Add secret | ~150 ms |
| Export `.2fa` | ~150 ms |

## Cross-platform notes

- **Linux**: needs `~/.2fa` writable; clipboard via `wl-copy` / `xclip` /
  `xsel`. Native webview needs `webkit2gtk-4.1`.
- **macOS**: native webview zero-deps. Codesign optional.
- **Windows**: WebView2 (pre-installed on Win10 1903+). Zero-deps.
